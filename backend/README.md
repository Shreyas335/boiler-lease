# Backend – AWS S3 Media Storage

## Environment Variables

Add the following to your `.env` file (see `.env.example` in the project root):

| Variable | Required | Description |
|---|---|---|
| `AWS_ACCESS_KEY_ID` | Yes | IAM user access key |
| `AWS_SECRET_ACCESS_KEY` | Yes | IAM user secret key |
| `AWS_DEFAULT_REGION` | Yes | AWS region, e.g. `us-east-1` |
| `AWS_S3_PUBLIC_BUCKET_NAME` | Yes | Bucket for public listing photos |
| `AWS_S3_PRIVATE_BUCKET_NAME` | Yes | Bucket for private listing photos |
| `AWS_S3_PUBLIC_CUSTOM_DOMAIN` | No | Custom domain for public bucket (e.g. CDN) |
| `AWS_S3_ENDPOINT_URL` | No | Custom S3 endpoint (for MinIO / LocalStack) |
| `AWS_S3_PRIVATE_URL_EXPIRE_SECONDS` | No | Signed URL lifetime, default `300` (5 min) |

## Required IAM Permissions

The IAM user needs the following actions on both the public and private buckets:

**Upload signing (presigned POST)**
- `s3:PutObject`

**Signed read access (private photos)**
- `s3:GetObject`

**Optional (for future delete support)**
- `s3:DeleteObject`

Example minimal IAM policy:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject"],
      "Resource": [
        "arn:aws:s3:::YOUR_PUBLIC_BUCKET/*",
        "arn:aws:s3:::YOUR_PRIVATE_BUCKET/*"
      ]
    }
  ]
}
```

## Bucket Configuration

We use **two separate buckets** for simpler access control:

### Public bucket (`AWS_S3_PUBLIC_BUCKET_NAME`)
- ACL: `public-read` on objects
- No signed URLs needed — photos are served via stable public URLs
- Prefix: `listing-media/public/`

### Private bucket (`AWS_S3_PRIVATE_BUCKET_NAME`)
- ACL: private (default)
- All access goes through short-lived signed URLs generated by the backend
- Prefix: `listing-media/private/`
- Signed URL expiry is controlled by `AWS_S3_PRIVATE_URL_EXPIRE_SECONDS`

## S3 CORS Configuration

Both buckets need CORS configured to allow browser uploads from the frontend. Apply this to each bucket:

```json
[
  {
    "AllowedHeaders": ["*"],
    "AllowedMethods": ["POST", "PUT"],
    "AllowedOrigins": ["http://localhost:5173", "https://yourdomain.com"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3600
  }
]
```

Replace `AllowedOrigins` with your actual frontend URL(s).

You can apply this via the AWS CLI:

```bash
aws s3api put-bucket-cors --bucket YOUR_BUCKET_NAME --cors-configuration file://cors.json
```

## Media Privacy Model

- **Public photos** are visible to anyone viewing a listing. They are served via direct public URLs that do not expire.
- **Private photos** are visible only to the listing owner. Access requires authentication, and the backend returns a short-lived signed URL (default 5 minutes).
- Each `ListingMedia` record has an `is_private` flag that determines which bucket and URL strategy is used.
- Photos are not visible in listing API responses until the upload is finalized (`upload_status = "uploaded"`). Pending or failed uploads are hidden from normal responses.

## Upload Flow

1. Frontend calls `POST /api/listings/media/upload-init/` with listing ID, filename, content type, file size, and privacy flag.
2. Backend validates ownership and file metadata, creates a pending `ListingMedia` record, and returns a presigned POST payload.
3. Frontend uploads the file directly to S3 using the presigned POST fields.
4. Frontend calls `POST /api/listings/media/upload-finalize/` with the `media_id` to mark the upload as complete.
5. The photo now appears in listing API responses.
